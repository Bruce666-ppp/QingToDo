# 开发说明

原生 C# / WPF，兼容 Windows 10 / 11 的 .NET Framework 4.x。没有 NuGet 或其他第三方依赖。

## 构建

完全退出轻待办后，在 PowerShell 中执行本目录的 `Build.ps1`。脚本使用系统自带的 C# 编译器，在上一级生成 `轻待办.exe`。

`RunTests.ps1` 会在临时目录构建并运行 47 项核心、小窗、手动排序及快捷方式检查，不修改实际待办或启动项。

## 结构

- `Core.cs`：数据模型、原子保存和备份恢复、提醒到期判断、手动排序与旧数据兼容。
- `MainWindow.cs`：完整窗口、只显示三条事项的小窗、鼠标拖动、托盘、设置、轻闪动画。
- `ScheduleWindow.cs`：同一个小窗内的可选时间设置面板。
- `Integration.cs`：Windows 快捷方式、无激活显示、置顶恢复。
- `Program.cs`：应用入口、单实例和重复打开唤回。
- `Styles.cs`：简约样式和可访问名称。
- `SortFeedback.cs`：不拦截输入的拖动浮层、插入指示线和缓动过渡。
- `tools/IconBuilder.cs`：绘制便签图标，并导出 16 至 256 像素的多尺寸 ICO。

小窗与完整窗口分别保存位置。数据文件兼容旧版，新加的小窗设置缺省时保持完整窗口。小窗最多显示三条未完成事项；提醒可临时优先展示原本不在前三条中的事项。桌面入口使用独立的 `轻待办-便签.ico`，减少 Windows 复用旧图标缓存的问题。

手动顺序保存在每条待办可选的 `SortOrder` 字段。旧数据缺少字段时保持原先的创建时间顺序，首次排序或新增后写入顺序；排序不会修改创建时间、待办时间或提醒状态。新增待办追加到最后，完成后恢复的事项保持原有位置。完整窗口和小窗共用此顺序。专用手柄启动拖放，绿色插入线提示位置；正文仍可编辑或拖动窗口。

拖动时使用 `Adorner` 显示不拦截输入的卡片快照，原位淡化；其他事项通过 `RenderTransform` 在 150 毫秒内让位。放下后根据旧、新画面位置执行 230 毫秒缓出过渡；取消拖动会恢复原位置。排序期间到点的提醒暂存到拖放结束后再显示，避免打断拖动。开发参考：[Microsoft WPF Adorner 文档](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/controls/adorners)。

数据默认放在可执行程序旁的 `data` 文件夹。测试可用 `--data-dir "绝对路径"` 指定隔离数据目录，`--trace "绝对路径"` 记录不含待办文字的事件诊断。

提醒使用每秒一次的 UI 定时器。到点后将已提醒状态保存，再执行提示。休眠、关机和完全退出期间无法实时提醒，恢复后补提醒一次。最小化或隐藏后使用 Windows 的无激活显示方式，临时置顶约 4 秒后恢复偏好；不调用抢占前台焦点的 API，不播放声音。

桌面和开机启动入口均为当前用户的 Windows `.lnk` 快捷方式。默认不启用开机启动，不修改系统范围设置。更改程序所在目录后需重新生成快捷方式及启动项。
